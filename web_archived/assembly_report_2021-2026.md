## Reconstruction limits

Files retain original bytes and paths. Query strings and independent requested/replayed capture dates remain in metadata. Associations across capture times are unverified.
Version evidence comes from HTML, game JavaScript (including read-only XOR analysis checked against the archived WebAssembly loader), or explicitly referenced changelog captures. A folder label does not prove every selected file belongs to that release.
For primary script selection, exact cache-busting queries are preferred within 30 days; more distant exact matches yield to a closer capture at the same pathname. Superseded candidate assets are explicitly marked as preservation without a current game relationship. The original served script bytes remain unchanged.
Indexed payloads with no detected reference relationship are explicitly marked `indexed_capture_preservation` in assets.json. Conflicting query variants use `_asset_alternatives/<content-prefix>/<original-path>` so no original is overwritten. These preservation additions do not assert that the game used them in that snapshot.
External resources and Twitch avatars are excluded. No `.lightmap` capture was available in the indexed archive; missing files remain missing. Snapshots are recovered collections and are not guaranteed to run offline.

Two incomplete early write attempts were retained in ignored recovery quarantine folders after correcting URL-directory collisions. Their combined size is approximately 0.315 GB; they are outside the dated archive and are not used by the exporter. The recovery cache and assembly checkpoints also remain available.
